# 공개판 보안·개인정보 점검

[English](SECURITY_REVIEW.md) · [한국어 안내](../README.ko.md)

대상은 Google Apps Script 소스, 테스트, README, 저장소 게시 설정입니다. 공개 파일은 가상 이메일·예약자·장비·실험실·캘린더 ID를 사용합니다. 로컬 경로, 기관 도메인, 특정 운영 사건 기록과 원본 백업은 게시하지 않습니다.

## 수정한 항목

| 항목 | 보완 |
|---|---|
| 캘린더 이름의 시트 수식 주입 | 외부 텍스트를 시트에 쓰기 전에 수식 시작 문자를 일반 텍스트로 처리. 예약기록의 모든 텍스트 필드에도 적용 |
| 특수 예약자·캘린더 ID의 키 충돌 | 통계·그룹 객체의 프로토타입 제거로 `constructor`, `__proto__` 키도 독립 값으로 처리 |
| 개인 알림의 다중 수신자 주입 | 개인 주소는 단일 이메일로 검증. 잘못된 주소는 관리자에게 안내 |
| 메일 헤더 형식 | 수신자 형식 검증과 주소 목록·제목·발신자 이름의 줄바꿈 차단 |
| 주소 목록을 통한 바닥글 시험 메일의 실제 그룹 발송 | `TEST_GROUP_EMAIL`은 단일 주소만 허용하고 실제 그룹 주소는 거부. 현재 예약 정보가 포함되므로 시험 그룹의 회원·지난 메일 열람 권한을 허가된 관리자로 제한 |
| 그룹 이메일에서 만든 바닥글 링크 | 수신 거부·지난 메일 링크를 만들기 전에 그룹 주소 검증, URL에 넣는 그룹 이름 인코딩. 지원하지 않는 주소에는 관리자 문의 안내를 사용하고 표시 이름은 이스케이프 |
| 운영 개인정보 로그 | 원본 이름·주소·본문·일정 식별자·추가 시트 이름을 포함한 상세 로그는 `LOG_PERSONAL_DETAILS: true`일 때만 출력 |
| 실패 일정 누락 | 해당 캘린더의 처리 실패 시 동기화 토큰과 마지막 성공 시각을 유지하여 다음 실행에 재시도 |
| 전체 캘린더 응답이 비었을 때 마지막 예약의 삭제 판정 누락 | 전체 읽기가 성공하고 일정이 없어도 기존 활성 예약과 대조하여 취소 처리 |
| 게시 내용·설정 | README와 테스트까지 익명화, 인증·내보내기·로그·백업 제외, 공개 파일 패턴 검사 |

이메일 HTML은 동적 텍스트를 이스케이프합니다. 매니페스트는 Calendar 읽기 전용, 현재 스프레드시트, 메일 발송, 트리거 관리 범위를 사용하고 외부 HTTP 요청 권한을 추가하지 않습니다.

## 검증

`npm test`로 규칙·시뮬레이션·보안·공개 파일 검사 전체를 실행한 뒤 `SIM_ORDER=alpha`로 파일 로딩 순서를 바꿔 반복합니다. 보안 회귀 테스트는 저장·발송 경계의 악성 입력, 상세 로그 설정, 실패 후 재시도를 검증합니다. 시뮬레이션은 주간보고 시트 없음, 탭 정렬, 바닥글 메일, 취소 대조를 검증합니다. Google 서비스를 실제로 호출하지 않습니다.

최초 게시 커밋에는 익명화된 파일만 포함하고 작성자 이름·이메일도 가상 값을 사용합니다. 기존 원본에 Git 기록이 없으므로 과거 개인정보 기록을 가져오지 않습니다. 원본 백업과 로컬 점검 기록은 저장소 밖에 유지합니다.

## 운영 개인정보와 검증 한계

실제 설치 후 시트와 스크립트 속성에는 예약자의 이름·일정·이메일·내부 ID가 저장됩니다. 알림과 그룹 브리핑도 예약 정보를 공유합니다. 상세 로그를 켜거나 플랫폼에서 예외를 기록하면 운영 데이터가 남을 수 있습니다. 편집·열람 권한, 그룹 회원·기록 접근, 데이터 보관·삭제 정책은 운영자가 관리합니다.

안내 바닥글은 그룹 회원뿐 아니라 메일을 직접 참조(CC)로 받는 사람에게도 포함됩니다. 회원 안내와 수신 거부 링크는 그룹에 관한 것이므로 직접 참조 수신자에게는 맞지 않을 수 있습니다. `testFooterMail`은 가상 데이터가 아닌 현재 예약 정보를 시험 그룹으로 보냅니다. 기본값 `GROUP_FOOTER: ''`는 기존 바닥글 동작을 유지합니다. 선택적 안내는 구글 그룹스 표준 바닥글을 숨기기 위한 HTML 스타일을 사용하지만 그룹스나 메일 앱이 이를 바꿀 수 있습니다. 이 점검은 Google Groups, 삼성 이메일 등 메일 앱의 실제 바닥글 표시를 검증하지 않습니다.

시트 보호와 열 숨김은 열람 권한을 제한하지 않습니다. 패턴 검사는 인명이나 기관명을 완벽히 판별하지 않습니다. 본 점검은 소스와 모의 실행 범위이며 실서비스 권한, 계정 보안, 실제 메일 전달, Google 플랫폼의 모든 예외 경로까지 검증하지 않습니다.

GitHub 계정과 프로필은 서비스에서 표시하는 게시 계정 정보입니다. 콘텐츠 익명화와 별개이며 계정 자체를 익명화하지 않습니다.
